## 1. 개요

### 1.1 대상

React 18 + Vite 클라이언트와 Express + Drizzle(PostgreSQL/Neon) 서버로 구성된 풀스택 학원 관리 시스템이다.
Excel 시험지 업로드 → 본사·지점·반·학생 배포 → 온라인 응시 → 자동 채점(1~9등급) → Gemini 기반 AI 분석 보고서까지가 핵심 흐름이다.

### 1.2 목표

이번 사이클의 목표는 신규 기능 확장이 아니라 **v1 설계 대비 구현 정합성을 90% 이상으로 끌어올리는 것**이었다.
착수 시점의 실측치는 Match Rate 72%, Critical 7건, Major 18건이었다(분석서 §4·§5).

### 1.3 진행 방식

Check(gap 분석) → Act(iteration) 를 반복하고, 매 iteration 종료 시 동일 방법론으로 Match Rate 를 재산정했다.
가중치는 데이터 스키마 20% / API 25% / 기능 35% / UI·디자인 20% 로 사이클 내내 고정했다.

## 4. 배운 점

### 4.1 "성공"은 exit code 원문으로만 확정한다

여러 차례, 보고서상 "성공"으로 기록될 뻔한 항목이 실제로는 실패 상태였다.
`npm run build:client` 는 로그 마지막에 `✓ 1746 modules transformed` 를 남기고도 종료 코드 `-1073740791`(0xC0000409) 로 죽었다.
로그 꼬리만 보면 성공처럼 보인다. **화면 출력이 아니라 `echo EXIT=$?` 를 근거로 삼아야 한다.**

같은 이유로, 미해결 항목을 해결로 적으라는 요청이 있을 때마다 수치를 실측으로 되돌려 기록했다.
문서가 실패를 성공으로 적으면 다음 사이클의 판단이 통째로 어긋난다.

### 4.2 tsconfig 의 함정

- 클라이언트 빌드(`vite build`)는 **타입 검사를 하지 않는다.** `build:client` 가 통과해도 `tsc --noEmit` 은 37건 에러였다.
- `strict` 완화로 에러를 "해결"하는 것은 금지했고, 대신 타입 주석·null 가드·누락된 타입 정의(`vite-env.d.ts`) 로 처리했다.
- 데드 파일이 컴파일 대상에 포함돼 에러를 만들고 있었다. exclude 로 가리는 것보다 **파일 자체를 지우는 편이 정직하다**(최종적으로 23개 삭제).

### 4.3 날조 방지 원칙

보고서에는 근거 없는 수치가 여러 곳에 있었다 — 전체 평균 65% 하드코딩, 고정 백분위 곡선 `[3,8,16,…]`, 순위 조회 실패 시 백분위 100.
이를 전부 실계산으로 교체하되, **표본이 없으면 임의 값을 만들지 않고 `null` 로 두는 원칙**을 세웠다.
표본이 1명(본인)뿐이면 비교 의미가 없으므로 `비교가능: false` 와 표본 수를 함께 내려 AI 가 오도된 서술을 하지 않도록 했다.

### 4.4 중복 제거 규칙

같은 로직이 여러 곳에 복사돼 있으면 한 곳만 고쳐서는 결함이 남는다.

- 채점 폼의 `totalQuestions` 폴백 30이 5곳에 복붙돼 있어 31번 이후 답안이 조용히 누락됐다 → 헬퍼 1쌍으로 통일.
- 보고서 평균값을 서버에서 실계산으로 고쳐도, **템플릿이 같은 값을 65로 다시 하드코딩**하고 있어 화면에는 반영되지 않았다. 호출부와 템플릿 양쪽을 함께 고쳐야 했다.

### 4.5 환경은 코드만큼 자주 원인이다

`vite build` 크래시는 코드 결함이 아니라 Node 24 와 rollup 네이티브 바인딩의 문제였다.
같은 `node_modules` 로 Node 24 는 크래시하고 Node 22.23.2 는 EXIT=0 이었다 — **버전을 바꿔 대조하기 전까지는 원인을 특정할 수 없었다.**
또한 Windows 에서는 실행 중인 프로세스가 환경변수 변경을 상속받지 않아, 설치가 끝난 뒤에도 기존 셸에서는 도구가 보이지 않는다. 이를 설정 실패로 오인하지 않도록 레지스트리를 직접 확인하는 절차가 필요했다.

### 빌드 환경 주의

프로덕션 빌드는 **Node 22 LTS** 에서 수행한다. Node 24 에서는 `vite build` 가 rollup 네이티브 바인딩 크래시(0xC0000409)로 실패한다.
`package.json` 의 `engines.node` 는 `">=20 <23"` 이며, nvm-windows 로 Node 22.23.2 를 설치해 사용한다.

```
node --version   # v22.23.2 확인 (아니면 nvm use 22.23.2)
npm run build
```
