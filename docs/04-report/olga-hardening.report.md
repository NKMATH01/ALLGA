### 1.2 목표

## 6. 기술 교훈

### 6.1 마이그레이션 순서가 코드 배포를 이긴다

마이그레이션 0009 적용 전에 새 서버를 배포하면 `ai_reports.status` 컬럼 부재로 500 이 난다. Neon 풀러의 `connection.default_transaction_read_only` 는 시작 파라미터를 무시하므로, 향후는 `SET TRANSACTION READ ONLY` 를 명시적으로 실행해 대비한다.

### 6.2 "검증 통과" 보고는 exit code 로 재확인한다

실행자가 "빌드 성공"이라 보고해도 `EXIT=0` 가 없으면 신뢰하지 않는다. Node 24 에서 `vite build` 가 종료코드 `-1073740791`(0xC0000409) 로 크래시하는 상황처럼, 로그 꼬리만으로는 성공으로 보이는 함정이 있다.

### 6.3 중복 제거 규칙

같은 로직이 여러 곳에 복사되면 한 곳 수정으로는 결함이 남는다. 채점 판정식이 3벌로 복제돼 있으면 S-5 처럼 불일치가 생긴다. `helpers.ts` 로 단일화하면 변경 범위가 명확해진다.

### 6.4 감사 로그에서 PII 제거

`users.username` 이 전화번호인 환경에서 감사 기록에 username 을 남기면 개인정보가 유출된다. P-6 수정으로 id·role 만 기록하게 했다.

### 6.5 스펙과 구현의 수정 기록

`data-model.md` 에는 `ON DELETE CASCADE` 가 있었으나, 설계 검토 결과 `SET NULL` 로 변경했다. 지점 삭제 시 소속 계정을 "비활성"으로 남기는 감사 추적 정책과 CASCADE 는 충돌하기 때문이다. 이같은 설계 판단(3건: FK, 표준점수 null, 관리 목표 곡선 제거)은 커밋 메시지와 문서에 남겼다.
